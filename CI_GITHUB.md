# CI модуля 5: GitHub Actions

Репозиторий: https://github.com/Ogn1k/qa-automation-module5

Workflow: `.github/workflows/tests.yml`, название **Module 5 - Select Menu**.
Запуск: push, pull request или вручную через Actions → Module 5 - Select Menu → Run workflow.

Задания:

| Задание | Проверки | Ожидаемое число вариантов |
|---|---|---:|
| unit tests | Модель Select Menu, покрытие строк и ветвей | 22 |
| api tests | Book Store / Account API DemoQA | 5 |
| ui tests | Select Menu, TC-SM-01–13, 15, 16 | 18 |
| BDD scenarios | Сценарии TC-SM-09 и TC-SM-13 | 2 |
| Allure HTML report | Сборка отчета из артефактов pytest | 45 pytest-результатов при полном выполнении |

Окружение CI: ubuntu-24.04, Python 3.14, отдельный Chromium Playwright для UI/BDD.
Зависимости закреплены requirements.txt. На GitHub runner используется PyPI;
pip.ini с зеркалом остается примером настройки локального окружения.
Конкретные версии и длительности нового удаленного запуска следует брать из его журнала.

## Неуспешный Login

В локальном API-прогоне пользователя: **4 passed, 1 failed за 9,74 с**.
`test_login_empty` ожидает HTTP 400 согласно учебному примеру, получает HTTP 200.
Этот assertion сохранен. Существование красного API-задания означает, что тесты
запустились и выявили расхождение; это не успешное прохождение всего набора.
Ожидание требует сверки с контрактом DemoQA. Новые результаты нельзя заранее
приравнивать к локальным: возможны отличия публичного стенда и сети.

## Снимок 15: конфигурация

Открыть `.github/workflows/tests.yml` в VS Code, показать матрицу unit/api/ui,
шаги pytest/Behave и сохранение артефактов с `if: always()`.
Подпись: **Рисунок 15 — Конфигурация CI в GitHub Actions**.
Старый снимок `.gitlab-ci.yml` больше не соответствует выбранному сервису.

## Снимок 16: удаленный запуск

Открыть GitHub → Actions → Module 5 - Select Menu → конкретный запуск.
Показать его URL/номер, дату и фактические статусы заданий.
Подпись: **Рисунок 16 — Результаты удаленного запуска GitHub Actions**.
Дополнительно открыть `api tests` → `Run API tests against DemoQA`:
на снимке должны быть пять вариантов, причина ошибки и итог прогона.
Нельзя подписывать красный пайплайн как полностью успешный.

## Артефакты

На странице завершенного запуска, в разделе Artifacts:

- `reports-unit`: JUnit, покрытие и сырые Allure-результаты Unit;
- `reports-api`: JUnit и Allure API;
- `reports-ui`: JUnit, Allure и вложения при падениях UI;
- `reports-bdd`: JUnit Behave;
- `allure-html-report`: объединенные артефакты и `allure-report/`.

Для просмотра HTML скачать `allure-html-report`, распаковать и в его каталоге выполнить:

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory allure-report
```

Затем открыть http://127.0.0.1:8000.
JUnit также виден как таблица в Summary каждого задания.

## Что изменить в Word после запуска

В разделах 3, 5, 12, 17 и источниках заменить выбранный GitLab CI на GitHub Actions,
путь `.gitlab-ci.yml` на `.github/workflows/tests.yml`, указать ссылку на репозиторий.
В разделе 12 привести реальные статусы, время, ОС/Python runner и ссылку на запуск.
Локальные результаты 30.10.2026 оставить отдельно от новых удаленных результатов.
Сведения «удаленный CI не запускался» заменить только после подтвержденного запуска.
